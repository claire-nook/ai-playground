## Current Research State to Capture

The Batch Runtime / Scheduling experiment asks whether Supabase-managed scheduling can support common Nook Works scheduled/batch responsibilities in an iPad-first environment with reasonable management and observability.

The minimal experiment has two paths sharing a synthetic test table:

1. Cron A → PostgreSQL Database Function → insert `PENDING` test rows.
2. Cron B → Supabase Edge Function → Native Data API reads/updates → external weather provider → test rows become `SUCCESS` or `FAILED`.

An authenticated read-only Browser Observer exists as the Human Evidence Surface so Claire can observe scheduled state transitions without manually running SQL.

### Evidence status

Treat evidence conservatively:

- Cron A, Supabase Cron → Database Function → test-table insert: `Verified` for the tested path.
- Edge Function deployment lifecycle and current worker implementation: capture only what repository/provider evidence supports.
- Cron B end-to-end scheduled execution must remain `Partial` until runtime evidence proves the scheduled invocation and resulting state transition.
- Observer existence may be recorded as a Live Demo if its deployed route is supported by the current repository/deployment configuration. Do not claim its displayed Cron B result is Verified before observation.

The overall experiment/catalog entry should therefore be `verificationStatus: partial` at this stage.
