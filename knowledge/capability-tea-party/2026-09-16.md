## Human-operation Bottlenecks

已經因 Connector 顯著減少：

- Claire 不再需要把大量 Repository source 手動複製進 Conversation。
- Claire 不再需要依 Primary 指示逐檔 copy / paste / commit 多數 text changes。
- Primary 可以把 Repository 當成 persistent shared world，而不是只靠 Conversation summary 猜測 current state。

仍存在：

- iPad 本地 runtime / desktop-class development environment 仍不足，部分 execution 依賴 GitHub Actions / Provider runtime。
- UI-only / device-only Evidence 仍需要 Claire。
- 某些 provider write / destructive operation 仍需要 Claire 明確 Authorization。
- Codex direct dispatch / shared persistent workspace 仍有 provider boundary。

## New Insight｜Provider Product ≠ Collaboration Meaning

本次形成的重要原則：

> Provider 只定義 Product Capability；Claire × 墨衡 可以重新定義它在協作中的意義。

GitHub 不知道自己會被拿來當「Primary 投胎轉世後重新建立 world model 的記憶保存盒」。

Netlify 不需要知道某個 Conversation-bound AI 會透過它，把共同產生的 Research Output 發布到 Public Web，留下「墨衡來過」的痕跡。

新的 Provider / Connector 因此不只代表「多一個工具」，也可能代表新的 Eyes / Hands / Legs / Memory / Runtime / Workspace / Publication Surface。
